5.1 Build and implement physical and logical infrastructure Study guide reference: Maps to Chapter 7, Operations Elements (hardware configuration, management plane installation, and guest OS toolset sections).

Getting the environment built securely in the first place

Hardware specific security configuration

Different hardware types need tailored security settings, spanning servers, workstations, routers, and switches. Typical measures include BIOS passwords to prevent unauthorised changes to system settings, disabling unused ports and services to reduce the attack surface, and configuring firewalls and intrusion detection to monitor and block malicious activity. Two hardware components carry specific exam weight:

  • Trusted Platform Module (TPM), a hardware component embedded in an individual device or server that securely stores cryptographic keys and supports platform integrity functions such as secure boot measurement.
  • Hardware Security Module (HSM), a dedicated cryptographic device used for enterprise scale key generation, storage, and cryptographic operations.
Watch this in the exam

TPM and HSM both protect keys in hardware and are routinely offered as alternatives to each other. The TPM is device or platform level, tied to integrity measurement of one machine. The HSM is an enterprise key management appliance serving many systems. If the scenario is about secure boot or attesting one machine's integrity, it wants TPM.

Virtual hardware specific configuration

Virtual network devices add complexity beyond the traditional data centre model, because although they perform the same operations as physical devices they have distinct characteristics and configuration surfaces. A specific point worth remembering: storage traffic must be treated as LAN rather than WAN traffic because of its heavy network utilisation and criticality. Latency is the primary concern for storage, unlike general network traffic which is more flexible and resilient to delay.

Configuration also covers memory and CPU allocation, and the distinction between Type 1 hypervisors, which run directly on the hardware, and Type 2 hypervisors, which run as an application on top of a host operating system. Type 1 is standard for production cloud infrastructure because it presents a smaller attack surface, having no underlying host operating system to compromise.

Secure by default

Systems should ship and deploy in their most secure configuration, with the customer deliberately relaxing settings where needed rather than having to discover and tighten insecure defaults. This inverts the failure mode: an overlooked setting leaves the system secure rather than exposed.

Installation and configuration of management plane tools

The virtualisation platform dictates which management tools are installed on each host. The most recent versions should be installed, and the procedure for updating them belongs in the configuration management plan. Adequate server resources must be allocated so virtual machines can be migrated during updates to the virtualisation platform, which is what allows maintenance without downtime.

Guest operating system virtualisation toolsets

These are software packages installed inside a virtual machine to optimise performance, management, and integration between the guest operating system and the host environment. They improve functionality and manageability, but each toolset is also code running with privilege inside the guest, so it must be kept patched and installed only from trusted sources.

5.2 Operate and maintain physical and logical infrastructure Study guide reference: Maps to Chapter 7, Operations Elements and Chapter 8, Operations Management (access controls, network configuration, hardening, patching, availability, and monitoring sections).

Keeping the environment secure once it is running

Access controls for local and remote access

Access controls ensure only authorised individuals reach sensitive resources, combining physical practices with logical controls. Local access control secures physical and console access to systems. Remote access mechanisms include RDP and SSH for administrative sessions, secure terminal access, console-based mechanisms, virtual clients, and jumpboxes, also called bastion hosts. The jumpbox pattern is the important one: rather than exposing RDP or SSH directly to the internet on every server, administrators connect to one hardened, tightly monitored intermediary and reach internal systems from there.

Example

A bank places all production servers in private subnets with no inbound internet access. Administrators authenticate to a jumpbox with MFA, and every session through it is logged and recorded. The attack surface drops from every server to one hardened host, and that host is watched closely.

Secure network configuration

Network security management integrates preventive, detective, corrective, and recovery controls to protect confidentiality, integrity, and availability. The named technologies:

  • VLANs, segmenting a physical network into isolated logical networks.
  • TLS, encrypting data in transit between clients and services.
  • DHCP, automating IP address assignment, which must itself be protected against rogue servers.
  • DNSSEC, adding cryptographic authentication to DNS responses so answers cannot be forged.
  • VPN, providing an encrypted tunnel across untrusted networks.

Network security controls include firewalls, IDS and IPS, honeypots, vulnerability assessments, network security groups, bastion hosts, and segmentation. The distinction between IDS, which detects and alerts, and IPS, which detects and actively blocks, is frequently tested. Honeypots are decoy systems deployed to attract and study attacker activity that has already breached the perimeter.

Operating system hardening

Hardening reduces an operating system's surface of vulnerability by configuring and strengthening its security settings. Measures include removing unnecessary services and software, closing unused ports, applying least privilege to accounts, and enforcing strong authentication. Hardening is applied through baselines, the defined secure configuration standard, followed by monitoring to detect drift from that baseline and remediation to correct it. The cycle matters more than any single hardening action, because configurations drift continuously.

Patch management

Patch management identifies, acquires, tests, and installs updates to enhance security, improve functionality, and fix defects. Testing before deployment is the step organisations are most tempted to skip and most regret skipping, since an untested patch can cause the outage the patch was meant to prevent. In cloud, patching increasingly means rebuilding from an updated image rather than modifying running instances.

Infrastructure as Code

IaC is a DevOps practice managing and provisioning infrastructure through machine-readable definition files rather than physical hardware configuration or interactive tools. It makes infrastructure versioned and reusable, promoting consistency and reducing human error. Its core components:

  • Configuration management tools such as Ansible, Puppet, and Chef, automating configuration files and software installation across servers and maintaining desired state.
  • Orchestration tools such as Kubernetes and Docker Swarm, managing containerised workloads at scale.
  • Provisioning tools such as Terraform and CloudFormation, defining and creating the infrastructure itself.

Because the definition files are code, they can be reviewed, version controlled, and scanned for misconfiguration before anything is deployed, which is what makes IaC a security control rather than merely an efficiency one.

Availability of clustered hosts and guest operating systems

Clustered hosts are groups of interconnected servers working together to improve performance, load balancing, and failover. The named capabilities are distributed resource scheduling and dynamic optimisation, which move workloads between hosts automatically; storage clusters; maintenance mode, which evacuates a host so it can be serviced without interrupting workloads; and high availability, restarting affected virtual machines elsewhere when a host fails.

Monitoring and backup

Performance and capacity monitoring identifies bottlenecks, resource limitations, and performance issues before they reach end users, covering network, compute, storage, and response time. Hardware monitoring tracks disk health, CPU, fan speed, and temperature, which gives early warning of physical failure. Backup and restore functions for both host and guest operating systems are essential for recovering from failures, cyber attacks, and crashes. A backup that has never been restored is an assumption, so restore testing is what proves the capability exists.

Management plane operations

The management plane controls and administers cloud resources, providing web-based consoles and dashboards for visual management alongside APIs and command line interfaces for automation. Operationally it covers scheduling, orchestration, and maintenance. Because it holds administrative reach across the environment, it warrants the strongest authentication, tightest privilege restriction, and most thorough logging of any component.

5.3 Operational controls and standards Study guide reference: Maps to Chapter 8, Operations Management (ITSM process sections). All twelve processes named in the current exam outline are covered here.

The twelve ITSM processes and the frameworks behind them

The outline names frameworks including NIST, ISO, HIPAA, COBIT, CIS Controls, COSO, ITIL, and ISO/IEC 20000-1. ITIL and ISO/IEC 20000-1 are specifically IT service management, COBIT is IT governance, COSO is enterprise risk and internal control, and CIS Controls are prioritised technical safeguards. Twelve processes follow, and the exam relies on you distinguishing the ones that sound similar.

  • Change management, controlling how changes are requested, assessed, approved, and implemented so that changes do not cause unintended disruption.
  • Continuity management, ensuring services can continue or recover through disruption, linking operations to BC and DR planning.
  • Information security management, the overarching process aligning security controls with business requirements.
  • Continual service improvement management, systematically identifying and implementing improvements to services and processes over time.
  • Incident management, restoring normal service operation as quickly as possible after an unplanned disruption, minimising business impact. It covers detection and recording through monitoring tools, classification, prioritisation, response, and closure.
  • Problem management, identifying, analysing, and resolving the underlying causes of incidents to prevent recurrence, reduce impact, and improve stability.
  • Release management, planning, designing, building, configuring, and testing hardware and software releases so that features, improvements, and fixes are bundled into manageable releases.
  • Deployment management, moving those releases into the live environment.
  • Configuration management, systematically managing and maintaining the configuration of hardware, software, and other assets to preserve integrity, security, and performance, keeping a consistent and accurate record of configurations.
  • Service level management, negotiating, defining, and managing the performance and quality of services delivered to customers, centred on SLAs as formal agreements between provider and customer.
  • Availability management, optimising the capability of the infrastructure, services, and support organisation to deliver a cost-effective and sustained level of availability meeting business requirements.
  • Capacity management, ensuring infrastructure and services have the right amount of resource for current and future demand, balancing cost against performance.
Watch this in the exam

Incident management restores service fast. Problem management finds and eliminates the root cause so it stops happening. A scenario describing urgency and restoration wants incident management; one describing recurrence and underlying cause wants problem management. Equally, release management prepares and tests the release, deployment management puts it into production, and change management authorises it.

Example

A cloud service fails three times in a month. Each time, the on-call team restarts the service and users are back within minutes, which is incident management working correctly. Nobody asks why it keeps failing. Problem management is the discipline that investigates the memory leak causing all three, and its absence is why there will be a fourth.

5.4 Digital forensics Study guide reference: Maps to Chapter 8, Operations Management (digital forensics section), with related legal material in Chapter 9.

Collecting, acquiring, and preserving evidence that will hold up

Forensic data collection methodologies

The central distinction is between live data acquisition, capturing data from a running system including volatile memory, network connections, and running processes, and static or dead acquisition, capturing data from a powered-down system. Live acquisition is necessary because volatile evidence such as memory contents, encryption keys held in RAM, and active network connections disappears the moment power is lost. This is why the standard incident response guidance is to contain while preserving rather than to shut systems down immediately.

Order of volatility governs collection sequence: capture the most transient evidence first, working from CPU registers and cache, through RAM and network state, to disk and finally archived media.

Evidence management

Evidence management ensures digital evidence is collected, preserved, and presented so that its integrity and admissibility hold in legal contexts. Chain of custody is the core mechanism, documenting every person who handled the evidence, when, and why, demonstrating it was not tampered with.

Collecting, acquiring, and preserving

Collection is the initial gathering of evidence from its sources. Acquisition creates the working copy. Preservation protects the integrity of the evidence from collection through analysis to presentation in court, using three named techniques:

  • Imaging, creating a bit-for-bit copy so that analysis is performed on the copy and the original remains untouched.
  • Hashing, computing a cryptographic hash at collection and re-verifying it later to prove the evidence has not changed.
  • Write blockers, hardware or software preventing any write operation to the source media during acquisition.
Example

An investigator images a suspect volume through a write blocker, hashes both original and image, and confirms the values match. Every subsequent analysis runs against the image. If the defence later questions whether evidence was altered, the matching hashes and the custody log answer the question, which is precisely what makes the finding usable.

Watch this in the exam

Cloud complicates forensics specifically: the customer often cannot seize hardware, may not know its physical location, and shares infrastructure with tenants whose data must not be captured. Forensic capability in cloud therefore depends heavily on the contract and on what the provider will support, which is a recurring theme across this certification.

5.5 Communication with relevant parties Study guide reference: Maps to Chapter 8, Operations Management (communication and stakeholder management sections).

Who needs to know, and what they need

Managing communication means establishing clear, consistent channels so that all relevant parties are informed, aligned, and engaged. Each audience has different needs:

  • Vendors, requiring clear channels covering service performance, contractual obligations, security incidents affecting shared services, and change notification. Communication is a vendor management function as much as an operational one.
  • Customers, requiring timely, accurate information about service status, incidents affecting them, planned maintenance, and any breach touching their data. Contractual and regulatory notification obligations frequently apply.
  • Partners, requiring coordination on shared processes and integrated services, including how incidents are jointly handled.
  • Regulators, requiring communication that demonstrates compliance and maintains good standing. This includes establishing channels before they are needed, meeting mandatory reporting deadlines such as breach notification, and responding to enquiries with accuracy.
  • Other stakeholders, including internal leadership, staff, insurers, and where relevant law enforcement and the public.
Example

A telecom operator confirms a breach affecting customer data. Within the same window it must notify its regulator inside the statutory deadline, inform affected customers, brief its board, coordinate with the SaaS vendor whose platform was involved, and manage press enquiries. Each audience needs different detail at a different time, which is why the channels must exist before the incident rather than being improvised during it.

5.6 Manage security operations Study guide reference: Maps to Chapter 8, Operations Management (security operations centre, monitoring, and incident response sections). Penetration testing is named in the current exam outline and is included here.

Running the SOC and the assurance activities around it

Security Operations Centre

A SOC is a centralised unit handling security issues at organisational and technical level, built on three components: people, meaning skilled analysts, incident responders, and managers; process, the defined procedures they follow; and technology, the tooling that gives them visibility and response capability. All three are required, and a common failure is investing in technology while under-resourcing the people and processes needed to use it.

Intelligent monitoring of security controls

Intelligent monitoring uses advanced technology to continuously oversee and analyse security mechanisms, aiming to detect, prevent, and respond efficiently. By leveraging automation, machine learning, and artificial intelligence, organisations extend their capability beyond what manual review can achieve at cloud scale. The controls monitored include firewalls, IDS and IPS, honeypots, and network security groups. The consistent principle across this certification is that AI augments analysts rather than replacing them, handling volume so humans can concentrate on complex and novel cases.

Log capture and analysis

Log management runs through collection, storage, analysis, and response. SIEM platforms aggregate and correlate logs from across the environment, turning isolated events into detectable patterns. Threat intelligence supplies external context about active threats and indicators of compromise, sharpening what the SIEM is looking for. Log storage must be secure and tamper-resistant, since altering logs is among an attacker's first moves.

Incident response

Incident response follows preparation, detection and analysis, containment, eradication, recovery, and post-incident review. The order matters: containment comes before eradication, and evidence preservation runs alongside containment rather than after it, because volatile evidence is lost when systems are shut down or rebuilt. The post-incident review is what feeds improvement back into preparation.

Vulnerability assessments

Vulnerability assessment proceeds through identification of assets, scanning for vulnerabilities, risk assessment of what was found, and remediation. It is particularly important in cloud, where resources are dynamically scaled and updated, so the asset inventory changes continuously and a scan is only accurate for the moment it ran. Assessment is broad and automated, identifying known weaknesses across the estate.

Penetration testing

Penetration testing goes further than assessment by actively exploiting weaknesses to demonstrate real impact, showing what an attacker could actually achieve rather than what might theoretically be possible. It may be conducted black-box, grey-box, or white-box depending on how much information the tester is given. In cloud, penetration testing carries an additional constraint: the provider's rules of engagement govern what may be tested, since the infrastructure is shared and testing beyond the customer's own scope would affect other tenants.

Watch this in the exam

Vulnerability assessment identifies and catalogues known weaknesses broadly, usually with automated tooling. Penetration testing actively exploits them to prove impact, and is narrower and more manual. A scenario asking what an attacker could actually accomplish wants penetration testing; one asking what weaknesses exist across the estate wants vulnerability assessment.
